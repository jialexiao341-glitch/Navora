# Navora 娱乐与氛围功能实施计划

> 本文是规划文档，不表示已经开始开发。第一阶段的范围和交互规则是建议方案，实施前可按实际需求调整。

**目标：** 在现有 AI 工作台中增加轻量、可关闭、不干扰对话的休闲体验，首先交付 Web 端悬浮音乐播放器。

**架构：** 第一阶段在现有 Web 页面壳中加入独立播放器，使用浏览器原生音频能力和用户主动选择的本地文件，不新增后端接口。播放器在同一页面壳的视图切换期间保持状态；Electron 桌面端是独立 React 前端，另行规划。

**技术栈：** HTML、CSS、现有无打包工具的经典 JavaScript、HTML Audio、Node.js 测试；沿用现有国际化与主题。

## 一、现状与机会

- 已有对话、Agent、技能、知识库、工作空间、定时任务、通知、主题和壁纸；音频方面已有语音消息、TTS 和工作空间文件预览。
- 已检查的 Web 实现中未发现完整的全局音乐播放列表或悬浮音乐播放器。已有语音播放器可供参考，但不能直接视为完整音乐播放器。
- 目前首页偏任务导向，缺少集中且容易发现的休闲入口；播放器、专注计时和轻松对话可以逐步填补这一体验。
- 代码依据：`channel/web/README.md`、`channel/web/templates/views/chat.html`、`channel/web/static/js/chat/render.js`、`channel/web/static/js/workspace.js` 和 `desktop/README.md`。
- 本计划依据对上述关键路径的检查，不代表逐行审计了所有渠道或模型实现。

## 二、范围和决策

### 第一阶段：Web 悬浮播放器

1. 页面提供一个小型音乐入口，打开后显示可收起的播放器；收起面板不停止播放。
2. 用户通过文件选择器添加多个本地音频文件，支持播放 / 暂停、上一首 / 下一首、进度拖动、音量和移除曲目。
3. 展示文件名、播放状态、当前时间和总时长；支持顺序播放和列表循环。
4. 面板与主题、深浅色、移动端适配；键盘可操作、控制按钮有无障碍名称。
5. 跨应用内视图切换保持播放；刷新后恢复音量、循环模式和面板偏好，但不自动播放，也不假设浏览器仍能访问先前选定的文件。
6. 开始录音时暂停背景音乐；录音结束后不自动恢复，由用户决定。语音消息或 TTS 开始播放时暂停背景音乐，语音结束后不自动恢复。
7. 音频加载或播放失败时提示用户，并允许切换、移除曲目或重试。

### 第一阶段明确不做

- 不接入在线音乐搜索、第三方平台账户或未经授权的曲库；不内置尚未取得分发授权的音乐和环境音。
- 不将用户选择的本地音频上传到服务器，不保存文件内容或本地绝对路径。
- 不承诺刷新后恢复本地文件或播放进度；不做多标签页播放互斥，先在说明中告知每个标签页独立。
- 不修改 Electron 桌面端，不扩展工作空间文件服务，不实现 Agent 控制播放器。

### 待用户确认的产品选择

- 是否先只做 Web，还是需要同步交付独立的 Electron 界面。
- 播放器入口的具体位置及视觉风格；建议默认右下侧，避开输入框、滚动按钮和工作空间面板。
- 用户是否愿意手动重新选择文件，还是需要后续研究持久化文件权限 / 本地媒体库。
- 白噪音素材的来源和分发授权；未确定前第一阶段不内置素材。

## 三、实现边界与文件规划

| 文件 | 计划职责 |
| --- | --- |
| `channel/web/chat.html` | 将播放器容器放在视图容器之外，注册 CSS、JS；遵循现有 include 和 defer 加载顺序。 |
| `channel/web/templates/layout/ambient-player.html`（新增） | 播放器入口、面板、文件选择器及语义化控件。 |
| `channel/web/static/css/ambient-player.css`（新增） | 紧凑悬浮布局、明暗主题、焦点、禁用态、移动端适配。 |
| `channel/web/static/js/core/ambient-player.js`（新增） | 播放列表、对象 URL 生命周期、音频控制、设置存储和语音协调。 |
| `channel/web/static/js/chat/state.js` | 在录音实际开始时通知播放器暂停；不修改录音原有失败处理。 |
| `channel/web/static/js/chat/render.js` | 语音气泡音频开始播放时通知播放器暂停，覆盖手动播放和自动 TTS。 |
| `channel/web/static/js/core/i18n.js` | 为简体中文、繁体中文、英文补充播放器文案和错误提示。 |
| `tests/web_ambient_player.test.cjs`（新增） | 验证列表、边界、偏好恢复与语音协调的关键行为。 |

位置与注册方式以实施时实际页面壳为准；应用内路由会复用页面壳，刷新或离开页面会销毁播放状态。不要将播放器放在会被聊天视图重建的消息列表内。

## 五、后续路线

### 第二阶段：专注与环境音

- 增加可手动开启和结束的专注 / 休息计时，复用现有通知机制；明确切换页面、关闭标签页后的计时语义。
- 在授权和素材来源明确后加入雨声、咖啡馆等环境音，支持独立音量。
- 验证用户是否希望定时结束后自动停止音乐，再决定是否增加该选项。

### 第三阶段：轻松对话

- 在统一的休闲入口提供猜谜、故事接龙、趣味问答等预设，复用现有对话发送流程。
- 预设内容让用户可见、可编辑，不暗中发送额外个人信息；显示这些互动会使用当前模型及其正常费用。

### 第四阶段：形象与桌面端

- 如用户确实希望更强的陪伴感，探索可关闭的桌面伙伴，限定动画频率和遮挡范围。
- 如需 Electron 客户端支持，在其 React 前端单独设计播放器组件，并决定能否共享偏好与素材；Web 版本不会自动覆盖桌面端。

## 六、风险与验收边界

- **本地文件生命周期：** 浏览器对象 URL 仅在当前页面有效；刷新后需要重新选文件。若以后要跨刷新恢复，需单独评估浏览器文件权限及兼容性。
- **文件服务：** 当前 `channel/web/api/files.py` 中的文件接口读取完整文件；第一阶段不依赖它。若未来播放工作空间大文件，需另行评估分段传输和访问控制。
- **自动播放：** 以用户点击作为播放起点，处理浏览器拒绝播放的情况。
- **多标签页：** 第一阶段各自独立，可能同时播放；若实际使用中造成困扰，再设计标签页协调。
- **内容授权：** 在线音乐服务和内置音源必须分别确认接口使用条件和分发权限。
- **验收范围：** 单元测试覆盖关键状态逻辑；实际音频解码、布局和浏览器限制还需要在目标浏览器中手动检查。
