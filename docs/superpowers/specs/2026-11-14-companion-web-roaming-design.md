# 网页小伙伴活动范围与动作设计

## 目标与范围

让已启用的小伙伴在 Navora 各网页视图中更自然地活动，改善活动范围小、动作单一和衔接突兀的问题。活动限定在浏览器可视区域，不增加系统桌面窗口，不改变现有角色选择、拖拽与任务提示。

## 方案

- 仅扩大聊天区的随机步长：改动较小，但其他页面仍没有活动，动作也仍然割裂。
- 在整个网页视口内活动，并以可中断的行为序列衔接行走和休息：推荐。复用现有素材和状态事件，控制范围与移动节奏，同时为后续新增动画素材留接口。
- 新增独立透明桌面窗口和大量新动画：覆盖范围更大，但超出本次网页范围，素材和平台成本也更高。

## 行为设计

- 空闲时，在视口安全边界内选择不同距离的目标，允许在聊天以外的视图活动；根据距离和角色性格调整行走时间及间隔，避免固定时长导致速度不自然。
- 行走前转向，行走结束后停留并穿插现有待机、小动作，再选择下一行为；避免同时调度互相覆盖的动作。现有四帧行走和待机素材会限制动作种类，不把变换效果冒充新的角色帧。
- 避让可见输入区域、弹窗等重要交互区域；用户正在输入、拖拽、打开小伙伴面板、页面不可见或任务运行时暂停自主活动。窗口尺寸变化时保持小伙伴在视口内。
- 拖拽或状态变化中断行走时，从当前可见位置平滑停下，避免跳回目标点；保留手动放置后的短暂停留。尊重系统减少动态效果设置。
- 现有任务事件继续控制提示；动作、移动及任务状态保持分离，给将来扩充精灵图和状态动画留出空间。本次不引入外部角色素材或桌面宠物插件。

## 验证

覆盖目标点边界、避让、距离与时长、行为中断及不同角色配置；结合网页手动检查多个视图、拖拽、输入、任务状态、缩放和减少动态效果。已有用户改动保持不变。
