Navora ships a ready-to-use desktop client with the Agent runtime and an optional system-level transparent desktop pet window bundled in — **no need to install Python or dependencies manually**. Just download, install, and run your local AI assistant.

## Download & Install

<Tabs>
  <Tab title="Windows">
    1. Open [GitHub Releases](https://github.com/jialexiao341-glitch/Navora/releases) and download the Windows installer (`Navora-Setup-*-x64.exe`).
    2. Run the installer and follow the prompts (you can choose the install directory).
    3. Launch Navora from the desktop or Start menu.
  </Tab>
  <Tab title="macOS">
    1. Open [GitHub Releases](https://github.com/jialexiao341-glitch/Navora/releases) and pick the build for your chip:
       - Apple Silicon (M1/M2/M3/M4): download the `arm64` build
       - Intel: download the `x64` build
    2. Open the downloaded `.dmg` and drag Navora into your Applications folder.
    3. Launch Navora from Launchpad or Applications.
  </Tab>
</Tabs>

## Auto Update

The desktop client has built-in auto-update powered by GitHub Releases. When a new version is available it is detected automatically; you can also manually "Check for updates" from the menu in the bottom-left corner, review release notes, download, and restart to install.

## Desktop vs. Command-line Deployment

- **Desktop client**: best for personal use on your own computer — works out of the box with system tray, launch-at-login, floating desktop pet, and auto-updating.
- **Command-line deployment**: best for developers or long-running servers with more customization. See [Quick Start](/guide/quick-start).

## Access from a Browser

Once the desktop client is running, it listens on port `9876` locally and serves the exact same Web console. So while the app is open you can also point your browser at `http://localhost:9876` for the same experience.

If that port is unavailable (for example reserved by Hyper-V/WSL2 on Windows), the client automatically falls back to another port and still starts normally. The actual port is shown on the `Local access` line in `run.log`, and you can pin one by setting `web_port` in `config.json`.

By default only this machine can connect. To open it from other devices on the same network (a phone, for example), change the listen address to `0.0.0.0` or this machine's local IP under **Settings → Integrations** (an access password is required first); the addresses other devices can open are shown below it.

## Local Data Storage

All data of the desktop client is stored on your machine (retaining `~/.cow` and `~/cow` paths for seamless compatibility):

- **Config directory**: `~/.cow` in your home folder, holding `config.json` (model keys, channels, etc.) along with logs, cache, and runtime data.
- **Workspace**: `~/cow` by default, holding chat history, knowledge base, memory, skills, scheduled tasks, and files produced by the Agent.

Uninstalling or upgrading the client does not delete these two directories, so your data is preserved across reinstalls and upgrades. To fully clean up or migrate to another device, back up or remove the corresponding folders manually.
